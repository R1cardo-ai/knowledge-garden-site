## 1. 本轮目标与范围

在现有网站上继续增加终末地风格的视觉细节，让首页更有构图层次、目录更像精细编排的档案、阅读页更有出版物秩序、交互更有明确反馈。采用增量精修，保留现有内容、功能、入口、装饰和用户偏好。

“细节只加不减”按以下规则执行：

1. 现有标题、摘要、标签、日期、统计、线稿、底纹、侧栏、更新条和入口逐项登记，不能以简洁为由删除、隐藏或降低可达性。
2. 允许微调对齐、间距、线宽、字重和装饰位置，但同一信息仍需完整可达；不通过缩小字体、增加截断或折叠原有内容腾出装饰空间。
3. 新增细节优先放在标题区、边缘、分隔处和操作状态，正文与证据图片保留清晰阅读区域。装饰不遮盖文字，不截获鼠标，不进入键盘焦点序列。
4. 原有动效与用户已指定的更新条循环保留；系统减少动态效果时完整静态呈现。新增动效不能取消既有暂停与焦点保护。
5. 只做桌面端。验收桌面窗口与桌面浏览器缩放，不新建手机界面、手机优化或手机验收任务；已有相关代码不在本轮批量清理。

本次只交付规划文档，不修改运行代码，不递增站内版本，也不把计划写入已发布更新。后续实施按第 10 节完成版本同步和发布。

## 3. 全站视觉细化规则

以下数值为实施起点，最终以真实内容和双主题截图校准；复用现有变量，不再叠加一套独立主题。

| 项目 | 具体方案 | 验收重点 |
| --- | --- | --- |
| 色彩 | 浅色沿用纸白、白色面板、近黑正文；深色沿用深灰底、较亮面板、灰白正文；强调黄沿用 `#FFFA00` | 黄只标记当前位置、操作或提醒；浅底不使用黄字和黄细线 |
| 中文层级 | 首页主标题建议 48–72px；页面标题 32–40px；模块标题 22–28px；正文 17–18px、行高约 1.8 | 不比当前同用途字号更小；长标题自然增长，不固定高度裁切 |
| 英文与数字 | 继续使用自托管 Saira；英文辅助标题宽度 125%，字段约 112%，数字等宽排列 | 中文主信息优先；英文标签表达真实栏目含义 |
| 边界 | 主分区 1px 细线；关键标题或精选上缘 3–4px 短实线；局部采用双层线间距 | 不给每一项叠加厚框，不靠阴影制造层次 |
| 边缘细节 | 为标题带末端、精选底边、操作区边缘增加短斜线带或细分隔 | 避开正文，装饰不造成控件错觉 |
| 切角 | 可点击按钮与筛选保留标准切角，常用起点 7–8px | 留出切角安全距离；不可点击正文面板不新增按钮形切角 |
| 背景 | 保留原创等高线，在标题或页面边缘继续组织；不在正文背后叠加新纹理 | 双主题下都能看清，不能盖过文字或证据图片 |
| 留白 | 桌面页边距建议 32–48px，模块间 32–56px，组件间 12–24px | 不把已有信息推入无必要的二级入口 |

三色细条保留其页面起始或详情标题下的用途，不扩散成全站多彩装饰。既有图形保留；新增图形使用原创 SVG 或 CSS。所有数字必须是栏目序号、真实日期、真实数量或已有版本，不添加假坐标、随机条码、虚构在线状态、评级与进度。

## 4. 逐页美化清单

### 4.1 首页：增加档案封面的精细程度

- **导航**：统一品牌、导航与操作按钮的基线；增加清楚的当前项下缘与键盘焦点；保留全部导航入口和主题控制。
- **左侧标题**：保留实心与空心英文标志字、中文主张和说明；增加上下信息带之间的细线关系，用真实日期和计数形成对齐的辅助信息行。
- **右侧精选**：保留原创线稿、真实标题、分类、日期、摘要和阅读入口；增加上缘短实线、底部轻量斜线带及字段之间的细分隔，保持长标题完整适应布局。
- **最近知识与成果**：为现有列表增加统一栏目编号、标题到日期的对齐规则和悬停反馈；保留条目数、分类入口与现有摘要，不减少展示数量。
- **更新展示**：保留循环更新条、最新更新区、完整日志入口和设计资源索引；增加版本、日期、标题的明确层级，不让装饰被误读为新版本状态。
- **首屏构图**：延续左右主次关系，让导航、主标题、精选和底部更新条共享对齐线；长内容允许正常增高，不用固定首屏高度截断内容。

验收：同数据前后对照中，原有首页内容与入口全数保留；中文标题仍是第一阅读点；精选长标题、空档案和存储失败状态均完整可见。

### 4.2 档案目录：增加精密而清晰的列表细节

- 保留快速记录区，为输入、类型选择和保存动作增加明确的分区线与聚焦层次。
- 保留搜索、类别、形式、排序和视图切换，为工具区增加统一高度、标签基线和当前筛选标记；筛选条件与清除动作继续可见。
- 将现有列表序号、类型、日期、标题、摘要、标签、阅读、详情与删除操作做稳定对齐；标签多时自然换行，不新增截断。
- 为行悬停及行内键盘聚焦增加左边标记和浅底反馈；如使用位移，限于不影响布局的内层，位移不超过 4px。
- 保留现有侧栏内容与展开收起偏好，补充标题边界和行间节奏，不以窄化侧栏压缩内容。
- 保留列表/卡片两种视图；卡片模式应用同一标题、字段、按钮状态规则，不能只美化默认列表。

验收：搜索→筛选→阅读→返回后筛选和位置仍正确；阅读、详情、删除是独立可用动作；“列表 01”始终指当前排序位置，不伪装成永久档案编号。

### 4.3 成果：增加证据展示的秩序

- 保留真实精选成果及默认记录日期排序，增加成果标题与颁发机构、级别、角色、日期之间的对齐关系。
- 图片外增加直角细线边界和独立说明区域；沿用 contain，不能裁掉证书文字或为视觉统一拉伸图片。
- 保留原图入口、证明链接和失败回退；仅对确实可点击的入口增加切角与悬停反馈。
- 无图时保留完整成果信息，以轻量斜线底纹和现有说明增强空白区域，不生成虚构奖章、星级或百分比。

验收：横图、竖图、无图、图片失败均有清楚布局；全部已有字段与链接保留。

### 4.4 阅读与详情：增加章节秩序，不增加阅读负担

- 标题区增加统一的英文辅助标题、真实日期与分类排版、底部分隔；保留摘要、返回和编辑入口。
- 正文继续采用单一阅读栏，建议约 640–720px；保留所有段落、代码、链接、图片和说明。
- 现有多章节目录增加当前章节标记；锚点滚动预留顶部空间。短文继续不强加目录。
- 宽桌面可让目录在自身区域内保持可见；窗口缩小或 200% 缩放时回到正常文档流，避免覆盖正文。
- 代码块强化语言说明和滚动提示，保留内部横向滚动及键盘访问；长链接继续换行。
- 关联记录增加日期与标题对齐、行间分隔和焦点反馈；保留目标丢失提示。
- 快速详情弹层同步标题、字段、操作区域的视觉规范；保留完整字段、删除确认与焦点返回。

验收：长文、无正文、长 URL、多级标题、代码与图片均可读；增加目录当前态不能破坏返回位置或浏览器前进后退。

### 4.5 表单、设置及异常状态：补齐细节

- 新增/编辑表单：统一字段标题、说明、输入边界和操作区间距；保留所有字段及现有错误关联。
- 聚焦：边界增强；错误：黄色提示标记加具体文字；成功：原有保存反馈配一次短促高亮，不改变真实保存判定。
- 删除：沿用专属危险状态和确认步骤；普通错误不用删除色。
- 导入导出：保留现有说明、覆盖确认和错误恢复，增加按钮处理状态与文字对齐，不修改快照结构。
- 主题、背景和侧栏偏好：延续现有入口与保存机制，为选中项补齐形状或文字标记，不仅靠颜色区分。
- 空档案、无搜索结果、读取失败、写入失败：分别保留准确说明和可执行动作，添加一致的细框与小面积纹理，不统一成模糊“暂无内容”。

### 4.6 更新日志、控制台及样张：统一完成度

- 更新日志保持全部历史，增加版本列、日期列与内容区的对齐；最新记录有明确标记，不折叠或减少历史条目。
- 控制台保留圆盘与真实统计，增强标签、当前选择和状态说明的对应；数据未知时仍显示未知。
- 样张、阅读说明、动效与对照页保留入口和内容，补齐公共导航、标题与按钮样式的一致性。
- 实际组件矩阵补充本轮新增状态，作为后续回归入口，不另建与真实组件脱节的展示副本。

## 5. 动效计划

| 场景 | 增强方式 | 约束 |
| --- | --- | --- |
| 按钮悬停/按下 | 颜色从一侧扫过，配合边界变化 | 100–200ms，焦点不被裁切 |
| 筛选切换 | 当前项填色与状态文字同步 | 160–240ms，不延迟真实筛选结果 |
| 记录行 | 轻量底色和左侧标记出现 | 120–180ms，不推动相邻行 |
| 弹层 | 沿用现有开关逻辑，补统一的短距离进入/退出 | 进入 240–280ms，退出 160–180ms |
| 保存完成 | 一次高亮经过按钮，并保留真实状态文字 | 不显示虚假进度，不吞掉错误反馈 |
| 首页入场 | 在已有序列中细化分隔线和信息区出现次序 | 保持现有 480ms 内完成的基线，不延长等待 |
| 更新条 | 保留已有循环、悬停暂停、聚焦静态浏览、离开恢复 | 不新增循环装饰；减少动态效果时完全静止 |

新增动画主要使用 transform 与 opacity；初始内容必须可读，脚本失败不留下透明页面。减少动态效果下关闭新增位移、扫色和入场，不影响状态含义。

## 8. “只加不减”核对方式

实施前创建保留台账，至少记录：页面、元素或能力、当前位置、基线截图、拟增加细节、完成后位置、回归结果。记录现有主要图形和动效，防止只统计文字却遗漏视觉细节。

每个批次完成后逐项确认：

- [ ] 原有页面、导航、按钮、快捷入口、侧栏与样张入口完整保留。
- [ ] 原有标题、摘要、标签、日期、统计、字段与完整更新历史均可达。
- [ ] 原有线稿、标志字、底纹、三色细条与循环更新展示得到保留。
- [ ] 没有新增内容截断、默认折叠、仅悬停可见的信息或减小正文来腾空间。
- [ ] 同数据、同窗口截图能标出具体新增细节；没有用空状态截图替代真实多条内容验证。
- [ ] 新增装饰不拦截点击、遮挡焦点或侵入正文；标题和原图完整。
- [ ] 数据、偏好与功能行为不因样式变化而丢失。

若新增装饰与可读性冲突，调整新增装饰的位置或尺寸，优先保持原有内容与行为。原有视觉细节确需变更时记录等价保留方式，不擅自删除。

## 9. 桌面验收矩阵

### 视觉与交互

- 窗口：1280×800、1440×900、1600×900、1920×1080；浅/深主题；普通/减少动态效果。核心首页、目录与阅读覆盖完整组合，其余页面覆盖双主题并检查独有布局。
- 缩放：桌面浏览器 100%、125%、150%、200%；检查导航、搜索、表单、弹层、正文目录与返回入口。200% 的布局重排属于桌面可访问性，不构成手机交付。
- 状态：零条、单条、多条；长中文/英文标题；多标签；无成果、无图、图片失败；长正文、代码、长链接；无搜索结果；读取与写入失败。
- 输入：鼠标与键盘；Tab 顺序、焦点可见、弹层焦点限制、Escape、关闭后焦点返回；更新条聚焦静态浏览与离开恢复。
- 阅读：正文普通文字对比度至少 4.5:1，大字至少 3:1；可辨识控件边界与焦点至少 3:1。装饰淡线不能承担唯一状态提示。
- 操作链：新增→搜索→筛选→阅读→返回→编辑→导出；隔离环境中核对导入、删除、覆盖取消与恢复。禁止用个人生产档案测试破坏性操作。

截图需标明产品版本、窗口、主题、动效偏好和实际数据场景；除页面全图，还保留导航、精选、列表行、表单与阅读细节局部图。不能仅用“无横向溢出”认定视觉验收完成。

### 工程验证

按实际改动执行相关现有测试，发布前完成 `npm run lint`、`npx tsc --noEmit`、`npm test`、`npm run build`、`npm run build:pages`，涉及 GitHub Pages 产物时执行 `npm run build:github`。`npm run check:updates` 必须通过；生产 HTTP 检查应先核对脚本目标和本次预期版本再执行。

新增状态逻辑（如章节当前态）补充有意义的行为测试；单纯边框、间距等样式用截图和真实交互验证，不为低影响视觉变更堆砌镜像测试。记录构建、浏览器错误和资源体积变化，新细节不得引入持续布局抖动或明显加载退步。

## 10. 更新公告、发布与最终交付

每次实际网站更新按以下顺序执行：

1. 从 `app/archive/page.tsx` 读取届时最新版本并递增连续修订号；同步 `currentVersion` 和最新 `updateLogs`，记录实际完成的改动。
2. 同步 `public/ui-kit/templates/` 中版本、完整日志、首页 ticker、feature、index 和相关更新列表；运行一致性检查，历史版本记录保持原意。
3. 通过本批桌面与工程验证，生成对应发布产物；按真实项目发布流程同步 `R1cardo-ai/knowledge-garden-site` 的源码和静态产物。
4. 依 standing authorization 继续部署同一发布到生产站点，无需重复询问确认；等待托管结果，并核对生产版本和本批变更入口。
5. 验证主页、目录、阅读、成果、更新信息和本批交互；只对实际通过的项目标记完成。托管结果尚未确认时，状态为待确认，不能报告全部发布完成。
6. 在 `docs/validation/` 保存截图、检查结果、提交号、部署标识及线上入口核对；更新 `docs/当前桌面验收.md`。

最终交付包含：保留台账、各页面前后对照图、修改文件清单、组件状态矩阵、测试与构建结果、版本同步记录、GitHub 与生产部署结果。需要回退时以同一已验证发布的源码与产物为单位回退，不改动用户浏览器档案。
