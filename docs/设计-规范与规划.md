### 必须优先处理的数据问题

`app/archive/page.tsx:489–495` 在保存数据无法解析时调用 `removeItem('knowledge-garden-entries')`，随后以 starterEntries 回退；第 533 行在 hydrated 后自动写入 entries。该路径可能删除损坏但仍可恢复的原始档案，再写入回退数据。这与提示词要求保护既有浏览器数据存在冲突，是源码核对发现的实际缺口，不是未来功能想象。

修复目标：读取失败时保留原始值，进入明确的恢复状态，暂停自动回写；允许下载原始备份、重新导入有效快照或由用户明确选择重建。读取/写入受限、空间不足时也应显示真实保存状态。测试只能使用隔离浏览器数据。

此处保留原规划编写时的文件引用作为历史记录。requirements.md 已并入 `项目-手册.md`；当前日志规范源为 `app/archive/page.tsx`。

## 五、分阶段实施路线

以下为建议工作量区间，不是交付日期承诺；按单人有效开发日估算，内容准备及外部发布等待另计。每阶段验收后再推进下一阶段。

### P0：数据与维护基线，约 2–3 日

1. 修复损坏数据删除和自动覆盖路径，增加读取/保存失败提示与原始数据下载。
2. 核对初始化、导入覆盖、背景设置、主题迁移等写入路径，保持旧键兼容，不重新初始化正常档案。
3. 修正文档中的日志源路径，梳理源码与根目录静态产物边界，保留现有 Git 状态。
4. 增加只读一致性检查：currentVersion、最新日志、六份模板的当前版本、ticker、feature、index 和更新列表相符。历史记录允许保留旧版本，不能简单要求所有版本字符串一致。

验收：有效档案刷新前后不变；损坏 JSON 不被删除或覆盖；写入失败有提示；取消导入不变更数据；六份模板检查通过。产物为修复代码、隔离用例和版本对照结果。

### P1：把首页接入真实档案，约 3–5 日

1. 保留现有 standard 视觉，把最近知识和最近成果放入首页内容主区，真实更新信息作为独立区域。
2. 从统一的校验与排序逻辑取得计数、分类和最近条目；明确首次访问、空档案、无成果、数据读取失败的状态。
3. 主入口指向档案操作，分类入口直达筛选结果；样张索引保留为次级设计资源入口。
4. 为档案视图和必要筛选引入 URL 状态，支持刷新与浏览器前进后退；本地条目 ID 直达仅保证同一份档案数据下有效。

验收：首页计数与 archive 相符；添加、编辑、删除后返回首页显示正确；分类链接直达对应视图；空数据不生成假条目；360/390/430px 无横向溢出。

### P2：真实条目阅读与内容结构，约 4–6 日

1. 保留快速查看 Sheet，补充适合长笔记和项目的阅读视图，按真实章节生成目录；短条目不强加目录。
2. 明确标题、日期、摘要、正文与辅助元数据顺序，移动端纵排，编辑入口可达。
3. 需要扩展正文结构时保留旧 notes 字段兼容，增加显式 schema 版本；富文本或 Markdown 必须限制不安全 HTML/链接。
4. 将关联记录逐步改为稳定 ID 关系，同时兼容旧标题文本，处理改名和目标被删除的情况。

验收：旧快照可读且字段不丢失；长文标题层级和目录正确；关联跳转可返回；不存在的 ID 有明确提示；编辑后列表、首页、详情一致。

### P3：全链路质量与发布准备，约 2–4 日

1. 修正 reading 当前页标记、ticker 名称和持续装饰动效；检查焦点、对话框关闭与焦点返回。
2. 对展示、归档、知识、成果、详情、表单、确认框和设置状态执行深浅主题与窄屏复验。
3. 按项目实际发布路径构建、验证预览，并确认资源路径、刷新直达、404 和数据存储 origin；更换域名不会自动迁移 localStorage，应提供迁移说明与快照步骤。
4. 整理原创/许可素材清单、发布记录及可回退产物，在进入实际发布阶段时核对目标环境。

验收：构建成功；关键路径可操作；控件触控区至少 44px；键盘和 reduced-motion 可用；控制台无相关运行错误；发布后版本与首页所有更新位置一致。未发布前明确标注“本地验收完成”。

### P4：内容驱动扩展，按模块评估

优先选择一个真实项目或成果作为专题试点。学习路径、反馈、媒体和同步均单独立项，先提供内容与需求，再估工期；不一次建设全部条件模块。

## 六、实施规则与验收清单

- 每次实际网站更新立即修改 archive 规范源及模板对应展示记录；版本号按届时实际最新值递增，不预占未来版本。
- 继续复用现有主题 token，避免新增第三套冲突样式；正文、静态框保持简洁，切角留给可操作控件。
- 每次涉及存储变更先验证旧数据兼容；不在用户当前浏览器测试覆盖、清空或迁移。
- 验收矩阵覆盖：浅/深主题，桌面与 360/390/430px，空档案/有记录/长标题/长正文/损坏数据，鼠标/键盘/减少动态效果。
- 核心回归链：新增 → 搜索 → 筛选 → 详情 → 编辑 → 导出 → 隔离环境导入；删除和覆盖取消路径单独验证。
- 截图标注实际版本、宽度与日期；公开截图遮盖个人标识，不用旧预览证明新版实现。
- 完成标准是操作闭环、数据可靠和真实内容可读，不以增加装饰组件数量衡量。

## 5. 页面构建方案

### 5.1 首页：一张持续更新的知识封面（P1）

桌面结构：顶部品牌与导航 → 真实日期/版本 → 左侧标题与介绍、右侧精选内容视觉 → 主操作 → 最新记录 → 最新更新。首屏建议主文案占 7 栏，视觉占 5 栏；内容少时留白，不靠假数字填满。

保留既有字标，但压低辅助英文的对比或面积，让中文主张成为第一阅读落点。右侧从通用文件线稿升级为“精选档案封面”：由一条真实记录的标题、分类、日期和原创几何图形组成。优先手动指定精选项；没有精选项时回退最近记录；无记录时展示真实空状态。

“开始记录”作为首屏主要动作，“浏览知识库”作为次要动作；版本记录放入更新区，避免三个同等强度按钮争抢注意力。可选装饰背景字设 aria-hidden，不重复朗读站名。主要标题始终为 HTML 文本。

移动端顺序：标题与简介 → 主要操作 → 精选内容 → 统计 → 最新记录。装饰可裁切，标题、日期、计数不可裁切。首页更新 ticker 允许暂停，减少动态效果时显示静态最新项。

### 5.2 知识库：可快速扫描的档案目录（P1）

默认列表形成稳定列关系：编号/日期 → 标题与摘要 → 分类/格式 → 查看操作。编号来源于稳定记录标识或明确的当前列表序号，不能伪装成永久档案 ID。

桌面把搜索、类别和格式筛选整合成一条工具带；当前筛选使用黄底墨字与文字状态。列表项由细线分隔，悬停或键盘聚焦时显示清晰定位。交互内部存在编辑按钮时，不嵌套整行链接。

移动端每项改为标题、摘要、元数据和操作的纵向布局；保留现有筛选/排序能力。恢复浏览器返回时的筛选状态和阅读位置。空结果明确显示条件并提供清除筛选。

### 5.3 成果记录：主成果与证据并列（P2）

精选成果采用较大标题与可核实作品图；右侧字段包括日期、类别及记录已有的说明。下方按日期展示普通成果。只有数据确有阶段和完成条件才增加里程碑；缺少目标总量时显示成果数量，不计算完成百分比。

图片不拉伸；预览保留说明和查看原图入口。没有图片时使用文字版式，不强制添加装饰奖章或虚构评级。手机端作品图与对应说明保持相邻。

### 5.4 阅读详情：清楚的标题、字段与章节（P1）

标题上方为短眉标，下方为日期/类别/格式；正文采用单一阅读栏。目录仅在正文存在多个真实章节时显示，桌面可放侧边，手机可折叠。相关内容延续档案行语言。

保留现有 EntryReader 内容渲染能力及链接处理；代码、长链接、图片和长中文标题分别验证。编辑和删除从主要阅读路径分离，删除维持明确文字与确认流程。正文不叠加等高线和大背景字。

### 5.5 更新日志与 UI 样张（P1/P2）

日志用版本 → 日期 → 标题 → 变更项的纵向层级；最新一项用小面积强调标记，历史记录使用细线。首页只放最新摘要并链接完整记录。

样张增加本站实际组件的状态矩阵：导航、档案行、精选封面、筛选、表单、空状态、弹层。showcase、reading、console 等模板共用同一数据同步来源。console 只展示已有真实数据，不因为模板有圆盘而增加虚构图表。

## 7. 动效与响应式

- 控件反馈建议 120–160ms，面板进出 180–240ms，首屏编排总长不超过 480ms；使用位移、透明度或色块擦入，避免弹跳和持续扫描。
- 悬停位移建议不超过 4px；触屏提供按下反馈，不依赖 hover 才显示重要操作。
- 媒体按需播放，文字与操作区固定；减少动态效果时去除非必要入场、ticker 滚动和主题揭幕。
- 初始布局区间建议小于 768px 单列、768–1199px 紧凑双栏、1200px 以上完整网格；最终依据实际溢出调整。
- 手机触控目标至少 44×44px；底部导航避开安全区和系统键盘；200% 缩放仍能操作。

## 实施顺序

1. **首屏识别动效**：三色条扫入、两行字标分层推入、黄色标语擦入。先完成这组，以图1首页第一眼的节奏为准。
2. **数据与浏览节奏**：实现首次读数锁定效果，再接入最近更新 ticker；保留真值、链接、键盘可达性和手动横向滚动。
3. **舞台与版本交互**：加入纸张/斜纹双层视差和最新版本号悬停/聚焦填色。
4. **适配与验收**：对照图1和图2的桌面首屏；检查浅色/深色主题、不同桌面宽度、键盘操作、页面切换和 `prefers-reduced-motion`。验收时确认 ticker 无缝、可暂停、减动模式静止，计数和版本号始终可读且不改变档案数据。
