# 知识库改为随笔：功能改造规划

日期：2026-10-29。状态：v1.0.236 已实施，发布核对见《现状-桌面验收》。

2026-10-30 实施说明：当前界面统一改为“随笔 / ESSAYS”，保留 `knowledge` 类型、原存储键、稳定 ID 和旧 URL。首页近期随笔与随笔目录默认按记录日期倒序，显式 `sort=updated` 继续有效；空摘要仅在展示时从正文生成预览。写作表单突出标题与正文，补充信息可展开，取消有修改的内容会提示。思源宋体网页子集以独立的 Garden Serif SC 内部名称分发并保留 OFL 许可证，避免修改字体仍沿用保留名称。字体覆盖 GB2312 常用简体字符及本站现有字符，其他字符回退到本地宋体。原规划基线与历史验收语境保留在下文。

核对基线：当前源码 `app/archive/page.tsx` 的版本为 v1.0.232；《当前桌面验收》顶部记录仍为 v1.0.231。本规划依据本地源码和项目文档，不代表重新完成了线上验收。

## 1. 改造目标

将“知识库”整项功能调整为“随笔”，承载日常观察、个人思考、读书感想、学习心得与阶段回顾。体验围绕“写下一段想法—按时间回看—安静阅读”展开。

改造覆盖栏目定位、首页入口、随笔列表、写作表单、阅读页、搜索筛选、统计和提示文案。原有知识内容全部保留并在随笔中展示；获奖成果继续独立。站名 Knowledge Garden 与全站品牌不因栏目调整自动更名。

本次交付为规划文件，未修改运行代码，不递增产品版本，也不发布功能更新公告。下述产品选择均为实施建议。仅做桌面端，保留桌面缩放与键盘可用性要求。

## 2. 推荐的第一版范围

| 项目 | 目标行为 |
| --- | --- |
| 全站栏目 | “知识库”改为“随笔”，英文栏目使用 ESSAYS |
| 首页 | “浏览知识库”改为“阅读随笔”；“最近知识”改为“最近随笔”；数量使用“篇随笔” |
| 随笔列表 | 默认按记录日期从新到旧排列；标题、日期、摘要成为主要信息 |
| 写作 | 主按钮“写随笔”；突出标题和正文；分类、标签、来源与关联放入辅助区域 |
| 阅读 | 保留独立阅读入口与章节目录，强化正文排版，支持返回原筛选及列表位置 |
| 字体 | 随笔标题、摘要和正文使用思源宋体；操作控件沿用全站现有字体 |
| 检索 | 保留搜索、分类、形式、排序和列表/卡片切换；低频条件收进“更多筛选” |
| 旧数据 | 旧知识记录直接作为随笔展示，保留原文、类型细节、ID、日期与关联 |
| 成果 | 继续使用原成果字段、筛选和排序语义；共享组件修改必须回归成果页 |

第一版保留当前浏览器本地存储模式。“保存随笔”表示保存到本地，不表示公开发表。网站代码上线不会把浏览器中的个人随笔发布给访客；公开文章、账号、云同步、评论及点赞属于独立后续范围。

## 3. 页面与交互设计

### 3.1 首页和全站入口

- 导航、页尾索引、控制台、设计样张中的当前功能入口统一显示“随笔”。
- 首页近期随笔展示日期、标题及短摘要，点击进入现有独立阅读页。
- 最近随笔按记录日期排序，与随笔目录默认顺序一致；日期相同时使用稳定次序，避免刷新跳动。
- 现有首页精选保持手动指定稳定 ID 的能力。自动回退策略维持原有规则，并明确其与“最近随笔”的不同含义，避免修改全站精选时误伤成果展示。
- 首页统计与分类概览继续来自真实内容，不加入虚构阅读量、写作天数或连续打卡。
- 当前导航及无障碍名称同步更新；历史更新日志中的“知识库”保留原文。

### 3.2 随笔目录

推荐桌面层级：紧凑栏目标题与简介 → 写随笔/快速记下 → 搜索和分类 → 连续随笔列表 → 辅助统计。

建议栏目文案：“记录日常的观察、思考与片刻感受。”

每行以日期、标题、两到三行摘要为主，分类和标签为辅助信息。保留现有卡片切换，不新增第三种视图。摘要优先取用户填写内容；缺失时可从正文提取纯文本预览，仅在展示时计算，不回写覆盖用户数据；正文为空时允许只展示标题。

“最近记录”作为默认排序，“最近更新”“最早记录”“按标题”仍可选择。编辑一篇旧随笔不会在默认列表中把它移到最上面。URL 中显式指定的旧排序仍受尊重。

搜索、分类放在常用工具带；形式等低频筛选可以折叠，但已生效条件必须可见且可一键清除。既有分类分布和月份概览降低视觉优先级，放到列表之后或可展开的“记录概览”，仍保留真实数据与已有分类筛选能力。

### 3.3 写作体验

沿用现有新增/编辑基础，扩大桌面正文输入空间，避免在紧凑表单中同时铺开全部元数据。

| 字段 | 第一版处理 |
| --- | --- |
| 标题 | 必填；显示为“随笔标题” |
| 正文 | 主要输入区域，继续复用现有 notes 字段和渲染能力 |
| 记录日期 | 默认当天，可修改；旧记录日期保持不变 |
| 摘要 | 可选，未填时使用展示预览回退 |
| 分类 | 可选；未选择时沿用未分类，不批量改写旧分类 |
| 标签 | 可选，保留现有容量与兼容规则 |
| 内容形式、来源、关联记录 | 放入“补充信息”，保留旧字段和值 |

新随笔默认沿用 note 形式。旧书籍、课程、文章、视频、项目记录可以继续编辑其原形式，不统一强制改成 note。分类可提供“日常、思考、读书、学习、回顾”等非强制建议，不自动给旧内容分类。

快速记录入口保留标题即可保存的能力，文案改为“记下一个想法”，保存后可继续补写正文。完整编辑器仍明确展示保存成功或失败；关闭有未保存修改的编辑器时提供继续编辑或放弃修改的提示。首期不加入自动保存草稿，避免形成两套存储与恢复规则。

### 3.4 阅读页

- 顶部显示随笔标题、记录日期、分类；正文是页面视觉重心。
- 随笔标题、摘要、正文与正文内的中英文标点使用思源宋体（Source Han Serif）。导航、按钮、筛选、日期及代码块继续使用现有界面字体或等宽字体，保证操作信息清楚。
- 正文以 16–18px、约 1.7–1.85 行高作为桌面调校起点；按实际字形检查字重、段距、标题层级、长文阅读宽度，以及粗体、斜体、链接和中英文混排。
- 延续现有纸白/墨色/高亮黄视觉体系，降低正文周围装饰密度；复用现有主题 token。
- 保留现有正文、代码、链接、图片和章节目录能力；短文不强制生成目录。
- 关联区采用“相关记录”，允许关联另一篇随笔或一项成果，不把成果错误标成随笔。
- 编辑、详情和删除确认继续可达。返回随笔列表时恢复搜索、筛选、排序及稳定条目的位置。
- 不存在或已删除的条目显示明确提示；本地数据缺失时不显示虚构正文。

## 4. 数据与旧链接兼容方案

推荐第一版通过界面和交互完成产品转型，继续使用现有存储协议。这样旧知识内容在新版中直接可用，无须清空、导出再导入或批量迁移。

1. 保留内部 `type: 'knowledge'`、localStorage 键 `knowledge-garden-entries` 和当前快照协议。界面通过统一标签映射显示“随笔”，不要求内部标识同步改名。
2. 保留稳定 ID、notes、summary、tags、source、relatedRefs、扩展字段和精选 ID；不因改栏目更新所有条目的 updatedAt。
3. 第一版继续使用 `/archive?view=knowledge` 作为兼容入口，显示随笔界面。独立阅读链接保持原路径和 ID。语义化 `/essays` 可后续单独设计，首期不叠加路由迁移。
4. 旧数组、v1/v2 快照继续通过现有导入校验；导出协议保持兼容，界面改称“导出档案”或沿用现有快照文案。
5. 保留读取失败时的写入保护与原始备份下载；不在真实个人数据上执行破坏性测试。
6. 修改默认排序时，同步 URL 解析、序列化、首页最近列表和默认控件提示。旧显式 `sort=updated` 仍表示最近更新。
7. 旧浏览器位置缓存无法恢复时安全回退到列表，不修改数据来适配缓存。

后续若一定需要把存储类型改为 essay，必须另行设计 schema 升级、幂等迁移与回退兼容，不能通过全局字符串替换实施。

## 7. 验收标准

- **栏目完整性：** 当前导航、首页、目录、阅读、表单、提示、控制台、样张及无障碍标签统一使用随笔；历史日志和底层兼容标识允许保留 knowledge/知识库。
- **旧数据无损：** 在隔离来源导入旧快照，比对 ID、类型、正文、日期、更新时间、标签、来源、关联和扩展字段；浏览新版及导出后不得因改名丢失或重写这些内容。
- **操作闭环：** 写随笔→保存→搜索→筛选→阅读→编辑→返回；另测删除取消、导入取消、未保存退出、保存失败和恢复路径。
- **排序正确：** 默认记录日期降序；修改旧文正文不改变默认位置；显式最近更新有效；首页最近随笔与目录一致，成果排序保持原语义。
- **筛选和返回：** 旧链接、刷新、前进后退、分类与形式筛选、阅读返回位置均有效；折叠区域中的生效条件可见。
- **桌面质量：** 1280、1440、1600、1920 宽度，深浅主题，键盘操作与减少动态效果；覆盖空、单篇、多篇、超长标题、长正文、缺失关联及损坏存储。复验弹层关闭无闪烁。
- **字体与阅读：** 确认随笔标题、摘要、正文实际加载思源宋体；检查中文、英文、数字、标点、链接、加粗与长文的字形和折行。核对字体文件、许可、网络传输体积及字体加载失败后的回退效果，不让字体交换造成明显布局跳动。
- **桌面缩放：** 检查 125%、150%、200%；等效视口仿真与真实浏览器缩放分别记录，不沿用旧版结论充当新版验收。
- **工程验证：** lint、类型检查、`npm test`、生产构建、Cloudflare Pages 和 GitHub Pages 构建、更新一致性与生产 HTTP 检查；浏览器验证不能由 HTTP 检查替代。

## 8. 发布与完成条件

实际实施时按当时最新版本递增，不预占版本号。在 `app/archive/page.tsx` 统一更新 currentVersion 和 updateLogs，再同步模板的当前版本、首页 ticker、feature、index 及相关更新列表。建议公告标题为“知识库升级为随笔”，具体列明写作、列表和兼容改动。

验证后将同一版本源码同步到 `R1cardo-ai/knowledge-garden-site`，按现有流程生成并发布对应静态产物，等待生产托管结果。核对 Cloudflare Pages 与 GitHub Pages 的版本、首页随笔入口、旧链接、阅读返回和成果入口，保存提交号、部署结果及线上证据后再报告完成。

保留上一版源码与产物作为回退点；回退测试使用隔离数据副本，不以覆盖或清空个人内容作为恢复手段。

## 9. 后续候选，不计入首期

自动保存草稿、按月归档导航、随笔专题、独立公开发布、跨设备同步、全文编辑器升级可在第一版使用后另行评估。优先依据实际写作习惯补充，首期完成“写作顺手、阅读清楚、旧内容完整、全站命名一致”。
