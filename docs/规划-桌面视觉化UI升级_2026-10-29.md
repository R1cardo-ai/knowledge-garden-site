## 1. 本轮要达到的效果

用户要求“更多可视化的 UI 美化”。上一轮已完成基础排版、边界、焦点、表单和阅读状态精修；本轮升级页面的构图、图文比例、数据表达和视觉节奏。完成后，在相同数据、相同窗口的前后截图中，应能直接指出首页、目录、成果三类页面的主要视觉变化，不能只靠讲解新增了哪些细线和间距。

采用“档案封面 + 内容概览 + 成果展陈”的统一方向。保留现有工业编辑风格和所有内容、功能、入口、装饰及偏好，允许重新编排位置，不把网站改成通用统计后台。

本文件最初为纯规划交付。v1.0.230 已按 §11 的顺序落地第一批：站内版本递增到 v1.0.230，公告、`currentVersion` 与五个模板的生成列表同步。后续批次继续按完成情况递增版本，并在验证通过后发布 GitHub 与生产站点。

## 2. 依据与现状判断

已核对 README、项目手册、当前桌面验收、设计规范与规划、上一轮增量美化规划，以及静态首页、FeaturedAward、EntryReader 源码。视觉基线采用 `validation/v1.0.229-beauty/contact-light-normal.jpg` 和已完成验收记录。本轮没有重新进行线上浏览器验收，也没有开展外部网站调研。

| 当前基础 | 本轮机会 | 需要避免 |
| --- | --- | --- |
| 首页左标题、右精选、底部更新条 | 让字标、线稿和精选形成一幅完整构图，增加内容驱动的概览 | 继续只补边框；放大英文后挤掉中文主张 |
| 目录主要由工具栏、记录行和侧栏组成 | 用可点击的分类分布与日期概览帮助看懂内容结构 | 新增一排相同统计卡片；图表把列表推得过远 |
| 成果已有真实图片、机构、级别和角色 | 增强大图展陈、字段与日期的叙事关系 | 裁切证书、虚构奖章、星级与完成率 |
| 阅读已有单栏正文和真实章节目录 | 强化标题封面、摘要、章节与配图的节奏 | 正文背景加纹理；把内容拆成大量卡片 |

前后对照必须使用同一份隔离合成快照；当前截图中的长标题场景继续保留。禁止为截图好看而替换、上传用户生产档案。

## 3. 不变的约束

- 只做桌面端。1280–1920px 窗口和桌面缩放属于本轮范围；不新增手机界面、手机增强或手机验收。
- 保留原英文实心／空心字标、中文主张、原创线稿、等高线、三色细条、精选、最近记录、侧栏、全部导航及样张入口。原更新条循环、悬停暂停和键盘静态浏览保持。
- 不删摘要、字段、标签和完整更新历史，不新增截断或默认折叠来为图形腾位置；长内容正常增高。
- 不修改 schema、存储键、稳定 ID、快照结构和既有排序语义；新增图形由当前有效数据派生，不创建第二份档案源。
- 无游戏官方素材、远程字体、默认人物图片；优先复用自托管 Saira、现有图标、原创 SVG 和 CSS。暂不引入图表或动画库。
- 单一强调黄只用于当前、操作、提醒。浅色不使用黄字或黄细线；删除继续使用危险色。不用发光、柔和投影、装饰性渐变和满屏卡片。

## 4. 视觉系统与尺寸起点

| 项目 | 设计方向 | 实施起点与限制 |
| --- | --- | --- |
| 页面骨架 | 展示页非对称分区，工具页稳定对齐 | 12 列桌面网格；页边距 32–48px，列间距 24–32px；缩放后按内容重排 |
| 首页主次 | 中文主张第一，档案主视觉第二，英文品牌辅助 | 中文 56–80px；英文 64–112px；不低于现有同用途字号，以 1280px 与长标题校准 |
| 页面标题 | 眉标、标题、摘要、元数据有明显级差 | 标题 36–48px；模块 24–32px；正文 17–18px；辅助字段 13–14px |
| 明暗面积 | 纸白为主体，局部墨色形成停顿 | 首页增加一个墨色内容带；不使用黑底黄色大字，不让多个深色块抢主标题 |
| 图形层次 | 一处主图，少量真实数据图形，原有纹理作为背景 | 首页线稿占其展示区约 30%–40%；纹理避开正文、输入和证书 |
| 图表语言 | 墨色／灰色区分，黄填充标当前项 | 必须有标签、数字、范围说明；不能只靠颜色、悬停或图形面积传达信息 |
| 留白节奏 | 大区块有呼吸，记录列表保持效率 | 展示区间距 48–72px；工具区 20–32px；不强制整屏高度，不为留白减少信息 |
| 可点击性 | 操作使用切角，非操作内容保持直角 | 图形可点击区域必须有文字动作、焦点与选中说明；装饰 pointer-events:none |

这些数值是设计起点，不是可读性例外。真实长内容、双主题和缩放检查优先于固定比例。

## 5. 首页：从双列信息页升级为档案封面

### 5.1 首屏构图

保留两侧内容，但把右侧线稿与精选标题组合成主要画面。左侧强化中文主张和主操作；实心／空心英文标志字成为上部横向结构，避免继续呈现为灰色小角标。日期、档案计数和版本形成清楚的页眉信息带。

```text
┌ 品牌 ─── 原有导航与主题操作 ──────────────────┐
│ 日期 / 真实知识数 / 真实成果数 / 当前版本       │
├─────────────────────┬───────────────────────┤
│ 英文实心与空心字标   │ 原创档案线稿           │
│ 中文主张（主阅读点） │ + 精选内容的真实分类   │
│ 原说明 / 主次操作    │ 标题 / 日期 / 摘要     │
│                     │ 阅读精选 →             │
├─────────────────────┴───────────────────────┤
│ 保留完整更新条与暂停、键盘行为                 │
└─────────────────────────────────────────────┘
```

具体改法：

1. 主视觉线稿重新编排线宽与留白，在原图基础上增加档案页层次；不添加假坐标、条码或随机编号。
2. 精选用文字区和插图区构成整体，不再只是一个普通信息框。长标题继续自然增长；无精选时线稿保留，文字明确邀请新增或导入。
3. 将现有真实计数提升为有视觉重量的数字与中文标签，支持进入知识或成果；数字变化仅在真实数据更新时触发一次反馈。
4. 1280px 不强塞大画面；允许图文上下重排并保留全部内容。桌面 200% 缩放时同样按内容流排布。

### 5.2 首屏之后的内容编排

- **内容概览**：新增分类横向条形分布，与计数和分类入口对应。点击进入已有目录筛选，目标 URL 使用当前约定；不另建分类系统。
- **最近知识**：保留现有条目数量、标题与摘要，用第一条重点记录加其余连续记录行组织；突出靠字号和位置，不删其余信息。
- **最近成果**：有可用证据图片时，采用一张真实成果图片与信息并置；无图时使用文本展陈和原有线稿，不生成假封面。
- **墨色内容带**：整合既有“最新更新”区域，白字显示真实版本和更新标题，黄色只用于入口或“最新”小标记；完整日志及资源索引继续可达。

完成标志：首页至少在首屏构图、精选图文关系、内容概览、更新内容带四处出现清晰的前后变化。

## 6. 目录：增加能帮助浏览的可视化

### 6.1 内容分布与日期概览

在现有快速记录与工具区之间加入紧凑的概览区，宽桌面横排两部分：左侧分类分布，右侧最近十二个自然月的记录量。初始建议高 160–220px，超长分类允许增高；缩放时按文档流排列。不得将搜索藏到折叠区。

```text
页面标题 / 原有快捷操作
快速记录（保留）
┌ 分类分布：文字 + 数量 + 横条 ┬ 按记录日期：12 个月柱形图 ┐
│ 点击分类筛选；显示统计范围   │ 月份、数量；可切换日期筛选 │
└────────────────────────────┴──────────────────────────┘
搜索 / 类别 / 形式 / 排序 / 列表与卡片（全部保留）
当前条件与结果数
连续记录列表                         原有侧栏
```

分类图按当前知识／成果分区全集统计，**不随搜索词缩小分母**，显示“当前分区全部记录”；当前筛选项高亮。图形是已有分类筛选的另一入口，切换后滚到结果标题，不自动打开第一条。

月份图采用现有 `date` 的日历年月，不使用创建时间或编辑时间替代。点击月份新增可分享的 URL 月份筛选参数；必须通过既有 URL 解析层扩展，并纳入返回恢复与清除筛选。若本批尚未完成这一状态能力，月份图保持明确标注的只读概览，不做无效按钮；交互版仍列为本轮后续阶段的必交付项。

### 6.2 列表和卡片的视觉差异

- 列表继续承担高效检索：保留连续行，在序号、类型图标、标题、日期和独立操作之间形成稳定的列节奏；选中／聚焦增加形状与文字提示。
- 卡片承担浏览：知识使用真实类型图标、分类、标题和摘要；成果优先展示真实证据图。没有图片时使用原有档案线稿和已有字段，不将类型图标误作封面照片。
- 不强制等高裁切摘要；多标签和长标题正常撑开。图像区域可统一外框比例，内部继续 contain。
- 原有侧栏与偏好保留，视觉上接入分类图当前态；不要让侧栏和概览同时出现两份互相矛盾的统计。

## 7. 成果：让证据成为视觉中心

成果页采用“精选展陈 + 日期纵线 + 原有列表／卡片”的顺序。精选与其余内容始终使用同一筛选和既有排序规则，不能为画面好看改选另一条成果。

- **精选展陈**：可用证据图放在较大的中性展示区，旁边完整呈现标题、摘要、机构、级别、角色与日期。不可点击外框保持直角；图片预览和原图入口明确标识。
- **证据图**：横图、竖图分别校准内边距；不裁掉证书文字、不拉伸，不在图片上覆盖装饰。图片自身颜色保留，界面控制仍使用单一强调色。
- **日期纵线**：在成果列表边缘用真实记录日期组织月份节点；同月只标一次月份，原每条日期仍保留。无效日期独立列为“日期待核对”，不强放到当前月。
- **无图成果**：用大标题、真实日期、字段和小面积斜线纹形成文字展陈；没有机构／角色时省略不存在的字段，不填“官方认证”等猜测。
- **加载失败**：保留与无图不同的提示、证明链接和原图入口；状态变化不导致页面大幅跳动。

日期纵线是原列表的分组表达，不新增第三套排序，也不默认收起历史成果。

## 8. 阅读、表单与更新页：统一视觉完成度

### 阅读页

标题区改为有明确上、下边界的文章封面：中文标题、日期、分类、形式、摘要各有层级；原返回和编辑入口保留。长标题不截断，摘要使用清楚的起始标记，不能伪装成用户未写过的引语。

正文保持 640–720px 和现有字号。二级章节增加适度间距与真实章节序号，序号说明为文内顺序，锚点仍使用现有解析规则；已有章节目录和当前态继续工作。正文图片采用“完整图片 + 原说明 + 原图入口”的图版布局，代码块只强化头部与边界。

关联记录增加一个局部连接示意：中心为当前记录，外侧只展示已有明确绑定且可解析的关联；文字列表完整保留。采用稳定的 SVG 布局，不做力导向漂移。最多显示六个图形节点，其余在图下注明数量并完整列出；未绑定和已删除目标留在文字列表中准确说明，不伪造连线。没有有效关联时不画网络，保留现有编辑提示。

### 表单与状态

以“标题与说明—分组字段—操作区”形成清楚的视觉结构，保留全部字段和上一轮长表单滚动修复。类型选择结合现有图标与文字；有真实图片链接时可增加预览，预览失败不阻止保存。成功、错误、处理中使用不同图标和文字，不能只改颜色。

空档案、无搜索结果、读取失败、写入失败各设计一幅小型原创 SVG 状态插图，分别与真实动作配对。插图为辅助，不代替说明；无新增、重新搜索、恢复等动作时不画虚假按钮。

### 更新日志、控制台与样张

更新日志强化最新一项的封面式标题，历史沿用日期与版本纵向结构，全部历史仍可达。控制台保留已有圆盘，让选中分段同时突出对应文字、计数和入口；不叠加第二个同含义饼图。实际组件矩阵增加上述图表、成果展陈、关联和状态插图，复用真实组件；静态其余样张同步公共视觉。

## 9. 图形的数据契约

| 图形 | 来源与计算 | 缺失、异常与操作 |
| --- | --- | --- |
| 分类横条 | 当前分区有效记录按现有 category 归一化计数；条长为该类数量／最大类数量 | 显示真实数量；相同数量按既有分类顺序；未知归入既有未分类语义；零条不画假条 |
| 十二月柱形图 | 以本地当前年月为末月，连续十二个日历月，对有效 date 计数，明确“按记录日期” | 月份显示含年份的范围；缺失月为 0；非法日期计入旁注“日期待核对”，超范围不混入图内 |
| 成果日期纵线 | 当前排序结果中连续的月份边界 | 只在日期排序下显示时间分组；其他排序保留记录顺序并改为无连线的日期标记 |
| 关联示意 | 当前记录 relatedRefs 的已绑定稳定 ID；旧数据沿用现有解析与兼容函数 | 重复目标去重；不推断隐含关系；未绑定／丢失不画有效边；点击同现有阅读入口 |
| 首页与控制台计数 | 复用现有档案归一化和读取状态 | 存储损坏、拒绝访问和未来快照显示未知，不误报为 0 |

所有图表必须有可读文字或等价列表；图内顺序、可见数值和读屏描述一致。分类项较多时纵向增高，不静默丢弃小类；布局不得靠 1px 文字、仅悬停 tooltip 或只有图例缩写维持。

读取逻辑保持 localStorage 来源边界，响应已有跨标签与 pageshow 更新。静态首页和 React 共享纯派生函数或同一受测模块，避免分别计算导致统计不一致。月份筛选只扩展 URL 状态，不写回档案字段。

## 10. 动效编排

| 场景 | 设计 | 边界 |
| --- | --- | --- |
| 首页出现 | 字标、线稿、精选与信息带依次落位 | 整体保持既有 480ms 内基线；内容初始可读，不依赖动画加载 |
| 分类／月份选择 | 当前块填色，结果标题同步状态 | 160–240ms；数据结果及时显示，键盘与鼠标等价 |
| 证据预览 | 沿用现有弹窗，图像稳定进入 | 不新增飞行、倾斜、持续视差；关闭后回到触发点 |
| 关联选择 | 焦点节点与对应文字同时突出 | 120–180ms；没有自动漂移或循环绘制 |
| 图表更新 | 数值和长度随真实数据变化一次 | 不从零反复播放，不报虚假加载进度 |

减少动态效果时新增位移、线条绘制和扫色关闭，所有图形与含义完整保留。原更新条遵守既有减少动效与键盘保护逻辑。

## 11. 实施路径与交付顺序

## 12. 验收：画面变化和功能准确同时成立

### 12.1 可见成果

- [ ] 首页有完整的新首屏构图、内容概览与明暗节奏；不是仅调字号、间距、边框。
- [ ] 目录图形能解释分类和月份分布，文字与图形数值一致；月份筛选、返回恢复与清除条件均工作。
- [ ] 成果图片成为主视觉，横图、竖图、无图、失败状态均经过实际截图检查。
- [ ] 阅读封面与正文层级明显分开；有效关联能以稳定图形与完整文字列表呈现。
- [ ] 表单、空／异常状态、日志、控制台及样张与新视觉一致，所有旧入口和信息保留。
- [ ] 每个核心页面提交整页与关键局部的同数据前后对照，标注版本、窗口、主题、数据场景及实际变化。

### 12.2 桌面和状态覆盖

首页、目录、阅读：1280×800、1440×900、1600×900、1920×1080，浅／深主题，普通／减少动效，共 48 组组合。成果展陈额外覆盖四窗口双主题；其余样张和表单覆盖双主题及独有布局。

桌面浏览器 100%、125%、150%、200% 检查导航、搜索、图表标签、图片预览、长编辑弹窗、章节和返回。此前 v1.0.229 的缩放确认只作为回归基线，新界面需要新验收；实际浏览器与 CSS 等效视口仿真分别记录。

数据覆盖零条、单条、多条、分类很多、超长分类、长中英文标题、多标签、十二月跨年边界、日期异常、范围外日期、重复关联、目标丢失、无正文、长代码和长链接。图形总数与可用数据逐项核对。

交互覆盖分类与月份点击、键盘选择、清除筛选、浏览器前进后退、阅读返回、列表／卡片切换、证据预览、表单焦点循环和关闭回焦。破坏性操作仅使用独立本地来源的合成快照。

正文对比度至少 4.5:1，大字至少 3:1，承担辨识作用的图形、控件边界和焦点至少 3:1。检查文字拥挤、图文主次、误导性点击外观和内容保留，不能仅以无横向溢出判定视觉通过。

### 12.3 工程与性能

纯聚合函数、月份 URL 筛选和关联去重补有意义的行为测试；边框和间距采用视觉验证。发布前执行 lint、类型、完整测试、生产构建、Pages 与 GitHub Pages 构建、`npm run check:updates`。

对照 v1.0.229 记录脚本、样式和图像字节变化；新增手写 SVG／CSS 图形的静态资源总计目标不超过 100KB（不含用户证据图片）。超出时优化并记录原因，不用压缩正文和图像可读性达标。证据图预留稳定空间并按现有策略懒加载；不因每次输入重算全站图表，不新增持续布局抖动。

## 13. 发布与证据

每个实际网站更新批次从 `app/archive/page.tsx` 读取执行时最新版本并递增；同步 currentVersion、updateLogs、静态模板版本、完整历史、首页 ticker／feature／index 和相关列表。公告只写已完成内容，不把后续阶段当成上线功能。

验证通过后同步 `R1cardo-ai/knowledge-garden-site` 源码及对应发布产物，并部署同一发布到生产站；沿用用户长期授权，不重复请求确认。等待托管成功后，核对线上版本、首页新构图、目录图表和筛选、成果预览、阅读与更新入口，再报告批次完成。

在 `docs/validation/` 按实际版本保存：保留台账、设计草图、前后截图、图表计算样本、交互与键盘结果、工程输出、资源差异、源码和产物提交、部署标识及线上验证；同步 `docs/现状-桌面验收.md`。

Git 当前有暂存删除与同名未跟踪目录并存。实施与发布必须核对精确文件边界，保护既有工作；禁止 reset、clean 或无差别批量提交。纯规划文档不改变站内版本，不生成静态发布产物。
