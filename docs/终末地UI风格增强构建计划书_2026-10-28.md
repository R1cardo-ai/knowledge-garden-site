## 1. 目标与判断

下一轮最值得投入的是让内容成为视觉主体：首页形成更明确的非对称构图，知识库形成稳定的档案行，成果形成有证据的展陈，阅读页形成清楚的章节秩序。黄色、切角、英文眉标和大字标已经有基础，继续增加装饰的收益低于重排内容层级。

建议采用“首页强展示、知识库强检索、详情强阅读”的强度分配。所有页面共用颜色、字形、导航状态和操作反馈；首页可以大胆，正文不承担海报效果。

本次交付仅新增计划文档，不修改网站运行代码，因此不提升网站版本、不将计划写成已发布更新。后续每个实际网站变更批次必须同步更新公告。

## 3. 网站基线与差距

源码事实：

- `app/page.tsx` 将根路径跳转到 `/ui-kit/templates/showcase.html?variant=standard`。首页增强必须修改真实的静态展示入口，不能只改 React 页面。
- `app/archive/page.tsx` 承担档案功能，并保存规范版本与更新日志；当前为 v1.0.209。
- `app/layout.tsx` 已配置 endfield 与 standard 变体；加载 globals、endfield-theme、endfield-desktop-controls 三层样式。
- `public/ui-kit/templates/showcase.html` 另行加载 `../assets/endfield.css`、`kit-nav.css` 和 `variant.js`。静态模板与 React 样式链分开，需要共同验收。
- `globals.css` 仍能找到旧圆角、暖色渐变与阴影声明；后续主题文件可能覆盖它们。不能仅凭旧声明判断最终页面仍显示旧样式，需查浏览器计算样式后再清理。
- 既有 v1.0.197 完成记录已经包含大字标、真实计数、原创档案线稿、手机触控及主题适配，不能重复列为待建设功能。

视觉参考基线为 `docs/validation/v1.0.205-recovered-desktop-2026-10-28.jpg`：已有巨大实心与空心英文标题、黄底中文重点、右侧档案线稿及统计面板。它证明风格基础已存在，但属于历史截图；不能作为 v1.0.209 当前渲染的最终结论。

待验证的增强机会：首页通用档案线稿能否更贴近真实内容；大英文与中文主标题是否竞争；首页和档案工作区是否有一致的信息节奏；列表是否被过多独立框体切碎。第一阶段通过当前截图确认这些判断。

## 4. 全局视觉规格

| 项目 | 拟采用规格 | 实现边界 |
|---|---|---|
| 基础色 | 纸白 #F4F4F2、板白 #FFFFFF、墨色 #161616、强调黄 #FFFA00 | 先映射已有 archive/ef token，避免增加第三套命名 |
| 深色 | 背景 #191919、面板 #222222、正文 #EDEDED | 独立检查边线、弱文案与输入框，不整体反色 |
| 强调色 | 当前导航、主要动作、需关注的信息 | 黄底墨字；浅色页面不用黄小字、黄细线承担信息 |
| 字体 | 已有宽体拉丁字体 + 中文黑体；数字 tabular-nums | 先核对实际字体文件及宽度轴支持；正文不机械拉宽 |
| 标题尺度 | 桌面主标题 48–72px，移动 32–40px；章节 24–32px | 英文字标可更大，但优先保证中文主标题与操作可见 |
| 正文 | 16–18px，行高 1.7–1.85；阅读栏约 36–40 个汉字宽 | 长标题自然折行；英文链接允许换行 |
| 网格 | 桌面 12 栏，内容最大约 1280px；页边距 24–48px | 移动边距 16–20px，按内容决定断点 |
| 形状 | 展示容器直角；按钮/筛选切角建议 6–10px | 文本距切角留足空间；焦点环置于不被裁切的外层 |
| 分隔 | 1px 线、短粗页签、少量墨色带 | 减少每条内容都包一个框的做法 |
| 纹理 | 首页两角局部等高线，建议 5%–9% 不透明度 | 阅读正文区域保持平整；不与满屏网格同时叠加 |

这些数值是初始设计参数，最终以实际字体、内容和对比度验收为准。普通正文对比度至少 4.5:1；大字及关键控件边界按适用标准检查，黄色不能成为唯一状态线索。

## 5. 页面构建方案

### 5.1 首页：一张持续更新的知识封面（P1）

桌面结构：顶部品牌与导航 → 真实日期/版本 → 左侧标题与介绍、右侧精选内容视觉 → 主操作 → 最新记录 → 最新更新。首屏建议主文案占 7 栏，视觉占 5 栏；内容少时留白，不靠假数字填满。

保留既有字标，但压低辅助英文的对比或面积，让中文主张成为第一阅读落点。右侧从通用文件线稿升级为“精选档案封面”：由一条真实记录的标题、分类、日期和原创几何图形组成。优先手动指定精选项；没有精选项时回退最近记录；无记录时展示真实空状态。

“开始记录”作为首屏主要动作，“浏览知识库”作为次要动作；版本记录放入更新区，避免三个同等强度按钮争抢注意力。可选装饰背景字设 aria-hidden，不重复朗读站名。主要标题始终为 HTML 文本。

移动端顺序：标题与简介 → 主要操作 → 精选内容 → 统计 → 最新记录。装饰可裁切，标题、日期、计数不可裁切。首页更新 ticker 允许暂停，减少动态效果时显示静态最新项。

### 5.2 知识库：可快速扫描的档案目录（P1）

默认列表形成稳定列关系：编号/日期 → 标题与摘要 → 分类/格式 → 查看操作。编号来源于稳定记录标识或明确的当前列表序号，不能伪装成永久档案 ID。

桌面把搜索、类别和格式筛选整合成一条工具带；当前筛选使用黄底墨字与文字状态。列表项由细线分隔，悬停或键盘聚焦时显示清晰定位。交互内部存在编辑按钮时，不嵌套整行链接。

移动端每项改为标题、摘要、元数据和操作的纵向布局；保留现有筛选/排序能力。恢复浏览器返回时的筛选状态和阅读位置。空结果明确显示条件并提供清除筛选。

### 5.3 成果记录：主成果与证据并列（P2）

精选成果采用较大标题与可核实作品图；右侧字段包括日期、类别及记录已有的说明。下方按日期展示普通成果。只有数据确有阶段和完成条件才增加里程碑；缺少目标总量时显示成果数量，不计算完成百分比。

图片不拉伸；预览保留说明和查看原图入口。没有图片时使用文字版式，不强制添加装饰奖章或虚构评级。手机端作品图与对应说明保持相邻。

### 5.4 阅读详情：清楚的标题、字段与章节（P1）

标题上方为短眉标，下方为日期/类别/格式；正文采用单一阅读栏。目录仅在正文存在多个真实章节时显示，桌面可放侧边，手机可折叠。相关内容延续档案行语言。

保留现有 EntryReader 内容渲染能力及链接处理；代码、长链接、图片和长中文标题分别验证。编辑和删除从主要阅读路径分离，删除维持明确文字与确认流程。正文不叠加等高线和大背景字。

### 5.5 更新日志与 UI 样张（P1/P2）

日志用版本 → 日期 → 标题 → 变更项的纵向层级；最新一项用小面积强调标记，历史记录使用细线。首页只放最新摘要并链接完整记录。

样张增加本站实际组件的状态矩阵：导航、档案行、精选封面、筛选、表单、空状态、弹层。showcase、reading、console 等模板共用同一数据同步来源。console 只展示已有真实数据，不因为模板有圆盘而增加虚构图表。

## 7. 动效与响应式

- 控件反馈建议 120–160ms，面板进出 180–240ms，首屏编排总长不超过 480ms；使用位移、透明度或色块擦入，避免弹跳和持续扫描。
- 悬停位移建议不超过 4px；触屏提供按下反馈，不依赖 hover 才显示重要操作。
- 媒体按需播放，文字与操作区固定；减少动态效果时去除非必要入场、ticker 滚动和主题揭幕。
- 初始布局区间建议小于 768px 单列、768–1199px 紧凑双栏、1200px 以上完整网格；最终依据实际溢出调整。
- 手机触控目标至少 44×44px；底部导航避开安全区和系统键盘；200% 缩放仍能操作。

## 9. 验收清单与发布要求

视觉矩阵：360、390、430、768、1280、1600px；浅/深主题；普通/减少动态效果。先对首页、档案列表、阅读详情做重点矩阵，其余页面检查共享组件与独有布局。

内容边界：零条记录、单条记录、多条记录、长中文标题、长英文 URL、缺少封面、长更新日志、筛选无结果。不能横向溢出、遮住操作或产生错误统计。

交互：键盘可达、焦点明显、弹层关闭后焦点返回、表单错误可读、主题切换与偏好持久化、导入导出和删除确认保留。信息不能只靠颜色表达。

工程验证：按改动范围运行 npm run lint、npm run build；涉及档案/关联/偏好时运行对应现有测试，收口运行 npm test。静态发布链涉及模板时补做 npm run build:pages 和适用的产物检查。所有命令在实施阶段执行，本文不将其标记为已通过。

每一批实际网站更新都先在 app/archive/page.tsx 登记真实版本和变更，再同步 public/ui-kit/templates/。同时核对当前版本、完整日志、首页最新更新、ticker、feature/index 及相关列表；运行 npm run check:updates。版本递增以实施时基线为准，不预占版本号。

回归截图与说明写入 docs/validation。完成判定是相同内容与尺寸下层级更清晰，操作和数据行为不回退；不能仅凭“更黄、更黑、切角更多”判定成功。

## 10. 下一步可直接执行的工作包

第一批：采集真实首页与 /archive 的当前截图 → 建立双样式链 token 映射 → 调整首页标题/主操作/精选区域 → 同步列表标题与元数据样式 → 验证两主题及 360/1280px → 更新规范日志与模板展示数据。

这一批完成后，应能明确看到：首屏更像知识花园的内容封面，首页与档案目录属于同一设计系统，读者更容易找到标题、最新内容和下一步操作。
